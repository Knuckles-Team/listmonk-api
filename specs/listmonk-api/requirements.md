# CONN-LISTMONK-API — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-LISTMONK-API-R001` | **Token scheme.** The client must send `Authorization: token <user>:<token>` and never `Bearer`, in `listmonk_api/api/api_client_base.py`. Caller chain: the listmonk-mcp console script (pyproject.toml scripts, scion_sdk.cli:serve) loads the scion_sdk.connector entry point listmonk_api/__init__.py::connector, which registers listmonk_api/mcp_server.py tool functions that call the client built by listmonk_api/auth.py::get_client. Shape: build_authorization in listmonk_api/api/api_client_base.py (line 37) returns the token scheme value and BaseApiClient.__init__ (line 49) puts it in the session Authorization header. | `tests/test_token_auth.py::test_header_uses_token_scheme_with_username` and `::test_header_never_uses_bearer` must pass. |
| `CONN-LISTMONK-API-R002` | **Credential shapes.** A token that already reads `user:token` must be sent as given. A token with no username must be sent as `token <token>`. Caller chain: the listmonk-mcp console script (pyproject.toml scripts, scion_sdk.cli:serve) loads the scion_sdk.connector entry point listmonk_api/__init__.py::connector, which registers listmonk_api/mcp_server.py tool functions that call the client built by listmonk_api/auth.py::get_client. Shape: build_authorization in listmonk_api/api/api_client_base.py (line 37) returns token <value> as given when the value contains a colon or no username is set, else token <user>:<value>. | `tests/test_token_auth.py::test_combined_user_token_is_used_as_given` and `::test_token_without_username_is_sent_as_given` must pass. |
| `CONN-LISTMONK-API-R003` | **Wiring.** `get_client` in `listmonk_api/auth.py:20` must pass `LISTMONK_USERNAME` to the client. Caller chain: the listmonk-mcp console script (pyproject.toml scripts, scion_sdk.cli:serve) loads the scion_sdk.connector entry point listmonk_api/__init__.py::connector, which registers listmonk_api/mcp_server.py tool functions that call the client built by listmonk_api/auth.py::get_client. Shape: get_client in listmonk_api/auth.py reads LISTMONK_USERNAME through scion_sdk.config.setting and passes it as username to ListmonkAPI; no new helper is needed. | `tests/test_token_auth.py::test_auth_client_reads_listmonk_username` must observe the header through `get_client`. |
| `CONN-LISTMONK-API-R004` | **Fleet name.** `pyproject.toml` declares `listmonk-mcp` as the single `scion_sdk.connector` entry point. The content pack, the manifest `connector`, the fingerprints and the ingest binding all carry `listmonk-mcp`. Proving test: `tests/test_fleet_name.py::test_connector_name_is_the_fleet_name`. Caller chain: the scion_sdk.connector entry point listmonk-mcp in pyproject.toml resolves to listmonk_api/__init__.py::connector, and listmonk_api/kg_ingest.py::ingest_entities and ingest_documents submit through the listmonk_api/kg_ingest.py::_BINDING IngestBinding (line 28) reached by the listmonk_ingest tool in listmonk_api/mcp_server.py. Shape: the entry point name in pyproject.toml, listmonk_api/kg_ingest.py::_BINDING and the connector name resolved by scion_sdk.connector_identity.connector_name all carry listmonk-mcp. | Every connector name in the package is `listmonk-mcp`. |
